FalconDataRescue

A recovery and forensic analysis studio that checks its work before it calls anything recovered.

FalconDataRescue takes damaged or deleted data and guides it through scanning, reconstruction, and validation. The goal is to help an investigator understand what may be recoverable while keeping the original evidence untouched.

How it works

The app can inspect corrupted files and folders, carve files from disk images, and scan deleted NTFS records on a live Windows drive. It analyzes file signatures and fragments, attempts reconstruction, checks the result’s integrity, then reports a confidence score and assessment. Results are labeled as validated repair, partial recovery, original valid, or failed recovery, so uncertain output isn’t presented as a successful restore.
  • A browser workspace lets you choose a recovery mode, review scan results, and inspect extracted text, fragment relationships, integrity notes, and a raw hex view.
  • A command-line tool can process damaged files or folders; a FastAPI backend supports the web workspace and asynchronous recovery jobs.
  • Optional AI or ML review can assist classification. Heuristic analysis is available when no model service is configured.
  • The README includes synthetic NTFS tests and controlled damaged-file samples for demonstration.

MediQ — Smart Hospital Ecosystem

MediQ replaces a physical waiting line with digital appointment tokens. Patients can find a hospital and doctor, take a token, then follow their place in the queue. Doctors get a dashboard to call, skip, and complete patients; administrators can add clinicians and manage facility details.

What happens behind the interface: Supabase stores hospital, profile, and token data. Realtime updates keep the live token tracker in sync; role-specific access rules separate patient actions from doctor and administrator controls. The project README also describes SMS and email turn notifications, cancellation, doctor history, hospital join codes, and a WhatsApp proxy function.

Built with: semantic HTML, CSS, and vanilla JavaScript on the frontend; Supabase Auth, PostgreSQL, and Realtime for data and live updates. The README lists AI wait-time prediction, QR check-in, analytics, and payments as planned roadmap items, not current features.

Emergency Vehicle Mesh Network

EVMN is a Flutter prototype for sending emergency-awareness alerts between nearby devices over Bluetooth Low Energy. Because it uses short-range BLE broadcasts, the demo does not need an internet connection or a central server to pass an alert locally.

How the prototype works: A user saves vehicle details locally and turns on Driving Mode. Regular vehicle profiles listen for alerts; an ambulance profile or locally activated temporary emergency profile can broadcast them. Nearby devices can deduplicate, expire, and relay eligible messages while the app is open. The compact alert contains an emergency type, short-lived message ID, expiry and forwarding limits, plus vehicle colour and plate details. The receiving device plays a two-beep cue and can announce the alert using installed offline speech.

Implementation: Flutter and Dart provide the app; native Kotlin and Windows runner code handle BLE and offline speech on supported platforms. The README states BLE is implemented for Android and Windows; iOS, web, Linux, and macOS are not supported by the current BLE implementation.
EVMN is an academic demonstration prototype, not a certified warning system. Its BLE messages are unauthenticated and delivery is not guaranteed; it does not contact emergency services or grant traffic priority.
